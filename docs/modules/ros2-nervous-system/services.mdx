# ROS 2 Services

## Introduction to ROS 2 Services

**Services** provide synchronous communication between nodes using a request-response pattern. Unlike topics, services require both the client and server to be active simultaneously for communication to occur.

### Key Concepts

- **Request-Response Pattern**: Client sends request, server responds with result
- **Synchronous**: Client waits for response before continuing
- **Bidirectional**: Service interface defines both request and response types
- **Named**: Services have unique names within the ROS graph

## Service Communication Pattern

In ROS 2, service communication follows a request-response pattern:

1. **Service Server**: Creates a service that listens for requests
2. **Service Client**: Creates a client that sends requests to the service
3. **Request**: Message sent from client to server
4. **Response**: Message sent from server back to client

## Creating a Service Server

Here's how to create a service server in a ROS 2 node:

```python
import rclpy
from rclpy.node import Node
from example_interfaces.srv import AddTwoInts

class SimpleService(Node):
    def __init__(self):
        super().__init__('simple_service')
        # Create service with name, type, and callback function
        self.srv = self.create_service(AddTwoInts, 'add_two_ints', self.add_two_ints_callback)

    def add_two_ints_callback(self, request, response):
        response.sum = request.a + request.b
        self.get_logger().info(f'Returning {request.a} + {request.b} = {response.sum}')
        return response

def main(args=None):
    rclpy.init(args=args)
    simple_service = SimpleService()
    rclpy.spin(simple_service)
    rclpy.shutdown()

if __name__ == '__main__':
    main()
```

## Creating a Service Client

Here's how to create a service client in a ROS 2 node:

```python
import rclpy
from rclpy.node import Node
from example_interfaces.srv import AddTwoInts

class SimpleClient(Node):
    def __init__(self):
        super().__init__('simple_client')
        # Create client with service name and type
        self.cli = self.create_client(AddTwoInts, 'add_two_ints')

        # Wait for service to be available
        while not self.cli.wait_for_service(timeout_sec=1.0):
            self.get_logger().info('Service not available, waiting again...')

        self.req = AddTwoInts.Request()

    def send_request(self, a, b):
        self.req.a = a
        self.req.b = b
        # Send request asynchronously
        self.future = self.cli.call_async(self.req)
        rclpy.spin_until_future_complete(self, self.future)
        return self.future.result()

def main(args=None):
    rclpy.init(args=args)
    simple_client = SimpleClient()

    # Send request and get response
    response = simple_client.send_request(2, 3)
    if response is not None:
        simple_client.get_logger().info(f'Result: {response.sum}')
    else:
        simple_client.get_logger().info('Service call failed')

    simple_client.destroy_node()
    rclpy.shutdown()

if __name__ == '__main__':
    main()
```

## Running Service Server and Client

To run the service server and client:

```bash
# Terminal 1 - Run the service server
ros2 run robot_nodes simple_service

# Terminal 2 - Run the client with parameters
ros2 run robot_nodes simple_client 5 7
```

## Common Service Types

ROS 2 provides various standard service types:

- `std_srvs/SetBool`: Set a boolean value
- `std_srvs/Trigger`: Simple trigger service
- `example_interfaces/AddTwoInts`: Add two integers
- Custom service types defined in your packages

## Advanced Service Example

Here's an example of a more complex robot control service:

```python
# Define a custom service request
from example_interfaces.srv import Trigger

class RobotControlService(Node):
    def __init__(self):
        super().__init__('robot_control_service')
        self.srv = self.create_service(
            Trigger,
            'robot_control_service',
            self.robot_control_callback
        )
        self.robot_state = 'idle'

    def robot_control_callback(self, request, response):
        # Simulate robot control logic
        if self.robot_state == 'idle':
            self.robot_state = 'moving'
            response.success = True
            response.message = 'Robot started moving'
        else:
            response.success = False
            response.message = f'Cannot move, robot is {self.robot_state}'

        self.get_logger().info(f'Control request: {response.message}')
        return response
```

## Service vs Topic Comparison

| Feature | Topics | Services |
|---------|--------|----------|
| Communication | Publish-Subscribe | Request-Response |
| Synchronization | Asynchronous | Synchronous |
| Timing | Publisher and subscriber can be active at different times | Both client and server must be active |
| Data Flow | One-way (publisher to subscriber) | Two-way (request and response) |
| Use Case | Continuous data streams | Action requests and responses |

## Best Practices

- Use services for actions that require immediate responses
- Choose appropriate service types for your use case
- Implement proper error handling in service callbacks
- Consider timeout values when waiting for services
- Use descriptive service names following ROS conventions

## Error Handling in Services

Proper error handling is crucial in service implementations:

```python
def robust_service_callback(self, request, response):
    try:
        # Perform service operation
        if request.a < 0 or request.b < 0:
            response.success = False
            response.message = 'Negative values not allowed'
            return response

        result = self.perform_calculation(request.a, request.b)
        response.sum = result
        response.success = True
        response.message = 'Calculation completed successfully'

    except Exception as e:
        response.success = False
        response.message = f'Error occurred: {str(e)}'
        self.get_logger().error(f'Service error: {str(e)}')

    return response
```

## Key Takeaways

- Services provide synchronous request-response communication between nodes
- Service servers listen for requests, clients send requests and wait for responses
- Services are ideal for operations that require immediate feedback
- Proper error handling ensures robust service implementations
- Services complement topics by providing synchronous communication options
